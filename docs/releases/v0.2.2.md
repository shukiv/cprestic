# Gniza v0.2.2

Release channel: stable

Two things you could only do over ssh, you can now do on the page: read the
service log, and turn it up. And reporting a problem no longer needs
anything installed — the server builds the report and hands it to you; you
file it on the public form.

## Changes

- **Logs → Service log** shows what the service wrote, read back from the
  journal. Narrow it by level, by how far back to read, by how many lines,
  and by one account's name — which is how a single backup's story is found
  among everything else that ran that night.
- **Keep up with it** re-reads while you watch, and the box stays at the
  newest line. **Download all of it** hands over the whole of what the
  journal still keeps for the span chosen.
- **Settings → Log level** sets how much the service writes: `error`,
  `warn`, `info` or `debug`. It takes effect at once, without a restart, and
  is stored so the service comes back at the same level.
- The bug report page prepares the report and offers it as a file, with
  **File it at cprestic** beside **Download it** — the two halves of one
  action, in one place. It no longer sends anything from the server, and it
  no longer asks for an intake credential.
- Reports are filed at <https://bugs.jabali-panel.com/report>, picking
  **cprestic** as the product. That form needs no key and nothing installed,
  so reporting works the same on every server — including one whose operator
  never had a credential to install.
- `/etc/gniza/bugs-intake.key` is not read any more. A server that has one
  can delete it; leaving it changes nothing.
- Settings shows where reports go instead of where a key belongs.

## Why

The authenticated intake needs a key, and this plugin is published to every
cPanel server that installs it. There is no key such a plugin can hold
without publishing it. The send button therefore only ever worked on a server
whose operator had been given a credential by hand, and on every other server
it was a button that could not work. Removing it and naming the form that
does work is the honest shape of the same feature.

Nothing else changes. The preview is still signed and still expires, so what
is downloaded is what was reviewed rather than logs gathered since, and the
redactor still runs over every section before you see it.

## Notes on the service log

- Nothing on that page is redacted. It is this server's own log, behind the
  root-only socket, read by somebody who could run `journalctl` themselves —
  and a log read to debug a credential is no use with the credential
  removed. A bug report still is redacted, because it leaves the server.
- The level is read out of each line rather than from journald's priority.
  The service writes plain text to stderr, so every line reaches the journal
  at one priority and `journalctl -p` would filter nothing. A line with no
  level on it is always kept: an unclassifiable line is the one worth
  seeing.
- The `-log-level` flag in the unit file is now the level the service starts
  at before it reads its settings. A stored level takes over from there.
