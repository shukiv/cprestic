# Gniza v0.2.2

Release channel: stable

Reporting a problem no longer needs anything installed. The server builds the
report and hands it to you; you file it on the public form.

## Changes

- The bug report page prepares the report and offers it as a file. It no
  longer sends anything from the server, and it no longer asks for an intake
  credential.
- Reports are filed at <https://bugs.jabali-panel.com/report>, picking
  **cprestic** as the product. That form needs no key and nothing installed,
  so reporting works the same on every server — including one whose operator
  never had a credential to install.
- `/etc/gniza/bugs-intake.key` is not read any more. A server that has one
  can delete it; leaving it changes nothing.
- Settings shows where reports go instead of where a key belongs.

## Why

The authenticated intake needs a key, and this plugin is published to every
cPanel server that installs it. There is no key such a plugin can hold
without publishing it. The send button therefore only ever worked on a server
whose operator had been given a credential by hand, and on every other server
it was a button that could not work. Removing it and naming the form that
does work is the honest shape of the same feature.

Nothing else changes. The preview is still signed and still expires, so what
is downloaded is what was reviewed rather than logs gathered since, and the
redactor still runs over every section before you see it.
