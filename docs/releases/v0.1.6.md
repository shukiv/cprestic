# cP:Restic v0.1.6

Release channel: prerelease

Restore-safety fixes and HTTPS bug-report intake integration.

## Changes

- Granular database imports use a temporary login restricted to the selected
  database. Database-user restores require positive cPanel ownership before
  changing an existing login.
- Whole-account restores check the identity embedded in the archive against
  the requested account before reassembly or application.
- Backups with unreadable source files no longer count as complete copies.
  New backups record completion evidence in the repository, so recovery can
  check it even when local job history is lost.
- Retention protects groups with unverified reads and deletes only snapshot
  IDs from the checked plan. Completion records remain available for recovery.
- Restore and drill capacity checks use historical snapshot size and account
  for simultaneous scratch copies, rather than relying on current account size.
- **Report a problem** sends reviewed diagnostics over HTTPS to
  `bugs.jabali-panel.com`, program `cprestic`, and displays the returned Plane
  ticket. Preview and download remain available without an intake key.

## Upgrade notes

- Do not downgrade agents or maintenance tools against repositories written
  with the new completion records. Older versions do not understand these
  safeguards. External repository copies must preserve completion records as
  well as backup snapshots.
- Legacy snapshots cannot be retroactively certified when their local job
  history is missing. Completion records are small additional snapshots and
  are retained rather than automatically expired.
- Granular SQL imports intentionally refuse views, routines, triggers, events,
  and privileged DEFINER objects. There is no root fallback. A failed applied
  import can already have changed tables in the selected database.
- Bug-report delivery now needs an intake token in
  `/etc/cprest/bugs-intake.key`, owned by root with mode `0600` (or that filename
  under a custom config directory). Existing `bug_email` and `sendmail_path`
  settings no longer control bug reports. Backup notifications are unchanged.
  See [intake setup](../guide/troubleshooting.md#enable-intake-delivery).

## Validation boundary

Passed for this version: the full Go test suite, end-to-end backup/restore
tests, race tests for the changed components, `make vet`, and `make vuln`.
The vulnerability scan reported no reachable known vulnerabilities.

Real cPanel restore compatibility certification is still pending, including
MariaDB variants and remote or unusual database connection profiles. Automated
end-to-end tests use a fake cPanel provider. Treat this version as a prerelease
until testing on a disposable cPanel host is complete; do not use a production
hosting account for destructive restore tests.

Authenticated delivery to the live bug intake has not been exercised: program
readiness was verified, and delivery, validation, redaction, redirects, error
handling, and reviewed-content preservation were tested with mocked HTTP.

See [the restore-safety design and limitations](../adr/0016-restore-trust-and-backup-completion.md).
